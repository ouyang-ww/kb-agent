# kb-agent 愿景：从文档问答到个人学习系统

> 状态：**愿景文档**。记录目标形态与判断标准，与 [PLAN v4](../PLAN.md) 配套；排期以 PLAN 为准。
> 配套文档：[知识图谱与本体学习笔记](./knowledge-graph-and-ontology.md)（技术底座）、[L1→L3 最小可行闭环拆解](./mvp-l1-to-l3.md)（落地路径）。

---

## 1. 一句话

一个本地优先的个人学习系统：**知道自己有什么知识、主人掌握了多少、今天该做什么**，并通过每天 10 分钟的闭环让知识真正留下来。

不是"更聪明的笔记搜索"，而是"会教学的助手"。

---

## 2. 为什么不是"更聪明的问答"

现在的 kb-agent 是文档问答系统，回答"库里有答案吗"；目标系统回答"这个人现在该学什么、掌握了没有、下一步做什么"。

**回答的对象从文档变成了人。** 这个转变决定了三件事必须新增：

| 模型 | 回答什么 | 现状 |
| --- | --- | --- |
| **知识模型** | 库里有什么、怎么组织、依赖关系、覆盖与缺口 | 只有 chunk 向量，没有结构 |
| **学习者模型** | 主人会什么、掌握到什么程度、何时会遗忘、错在哪 | **完全没有** |
| **策略层** | 今天该复习什么、推什么新概念、出什么题 | 只有"用户问什么就答什么" |

**助手的全部价值来自知识模型与学习者模型之间的差距**：知识模型说"这个领域有 40 个核心概念"，学习者模型说"你会 12 个、3 个在衰退、5 个是前置瓶颈"，策略层生成一条缩小差距的路径。

没有学习者模型，"学习建议"就只能靠 LLM 临场编造，永远给不出"你今天该复习哪 3 个概念"。**这是最终形态里最不能省、也最容易被忽略的一层。**

---

## 3. 最终形态：四个界面 + 一个对话

聊天框是入口，不是产品。

### ① 采集箱（Inbox）

丢进任何东西（笔记、PDF、网页、语音），自动进入处理流水线：

```
清洗 → 抽概念/关系 → 与已有知识链接 → 去重/冲突检测
     → 生成摘要与首轮测试题 → 排进复习计划
```

目标：**丢进去 3 分钟内就有反馈，不需要主人手工整理。**

### ② 知识地图（Map）

不是装饰性的力导向图，而是一张**有状态的图**：

- 每个概念是一个节点，带掌握度颜色（未接触 / 学习中 / 已掌握 / 在衰退）
- 前置依赖边形成 DAG，能看出**瓶颈节点**（很多概念依赖它，但你没掌握）
- **缺口层**：对照外部参照系（见第 5 节），标出"这个领域应该有、但你没有"的概念
- **卫生指标**：孤儿笔记、重复内容、互相矛盾的说法、过期内容、从未被回顾的笔记

### ③ 今日学习（Queue）

每天打开只看到一张卡片，永远不超过 10–15 分钟：

- 到期的间隔复习（2–3 题）
- 一个新概念（按前置依赖排序，前置没掌握就不推）
- 一个连接（"这两篇笔记从未互链，但它们在讲同一件事"）
- 一个可选挑战（时间充裕时）

### ④ 回顾报告（Weekly）

每周一份：新增了什么、哪些掌握度上升/下降、哪些笔记成了孤儿、知识结构如何变化、下周建议。

**这是"知识管理"从被动变主动的关键**——让主人看见自己知识库的健康状况。

### ⑤ 对话（Chat）

保留，但背后是一个**有工具的 agent**：能查地图、排计划、出题、改结构、写笔记，而不是只会检索后总结。

## 4. 能力映射

| 目标 | 系统里实际是什么 |
| --- | --- |
| 管理现有知识 | 去重合并、矛盾检测、孤儿/过期识别、过长笔记拆分、自动生成概念页（聚合所有相关笔记的"常青笔记"） |
| 了解知识体系 | 概念图 + 依赖 DAG + 覆盖度 + 缺口分析 + 主题聚类；**只有图不够，见第 5 节** |
| 帮助吸收 | 间隔重复 + 主动回忆 + 交错练习 + 生成式提问（费曼式"讲给外行听"），而不是再给一份摘要 |
| 学习建议 | 前置感知的路径规划 + 时间预算 + 遗忘曲线 + 目标对齐，输出"今天 10 分钟做什么"而不是 50 项清单 |
| 新知识测试题 | 入库时自动出题，题型覆盖：概念辨析、因果、应用场景、反例、纠错、填空；**每题必须带原文出处** |
| 相关知识整理 | 概念页自动聚合、跨笔记综述、关联发现、更新传播（一个概念更新后提醒相关旧笔记可能过时） |

## 5. 关键但容易被忽略的问题：参照系

**只看自己库里的东西，只能看到"有什么"，永远看不到"缺什么"。**

真正的"了解知识体系"需要外部参照系：

- 教材目录 / 经典书 TOC
- 领域课程大纲
- 招聘 JD 的技能树
- 领域标准本体（schema 级即可，不必是完整 OWL）

系统应能把"你的库"与"某个参照框架"做覆盖度比对，输出：

> "这个领域 40 个核心概念你覆盖了 12 个，其中 3 个只有名词没有展开。"

没有参照系的知识地图，只是把笔记画成图而已。

---

## 6. 学习科学作为硬约束

如果系统不遵守下面几条，它就只是"更花哨的笔记 App"：

| 原则 | 在系统里的体现 |
| --- | --- |
| **主动回忆 > 重读** | 默认交互是出题让主人答，而不是把笔记推给他看 |
| **间隔 > 集中** | 调度算法驱动复习时点，而不是"今天学完这一章" |
| **交错 > 块状** | 复习队列混合多个概念，而不是一次只做一个主题 |
| **生成 > 接受** | 让主人用自己的话解释，系统判断是否覆盖关键点 |
| **校准** | 每题先问"你有多大把握"，识别"以为自己会"的错觉 |

## 7. 架构分层

```
源层：Markdown / PDF / 网页        ← 唯一事实来源，人类可编辑
  ↓
加工层：清洗 → 切块 → 概念抽取 → 链接/消歧 → 出题 → 排程
  ↓
知识模型：概念图 + 依赖 + 出处 + 参照系覆盖率
学习者模型：掌握度 + 复习计划 + 作答记录 + 校准 + 目标
  ↓
策略层：今日队列 / 推荐 / 出题 / 讲解 / 周报
  ↓
界面层：CLI / REST / Web / 聊天 Agent / 通知
  ↓
评估层：检索指标 + 学习效果指标 + 数据卫生指标
```

四条原则：

1. **源层不可被自动改写**——所有加工结果都是派生物，可重建
2. **加工层幂等**——内容哈希 + prompt 版本，重复跑不产生重复数据
3. **模型层可解释**——每个掌握度能点开看到依据的作答记录
4. **策略层可关闭**——任何主动行为都必须有开关和每日预算

---

## 8. 边界：明确不做

- **不做通用笔记编辑器**：Obsidian / Logseq 已占位。源文件用 Markdown，系统只做加工层。
- **不追求完整 OWL 本体**：YAML 白名单级别的"本体-lite"足够。
- **不做全自动改写/合并笔记**：合并、矛盾处理必须人工确认，否则会悄悄破坏源数据。
- **不把聊天框当唯一界面**：学习是队列和节奏，不是问答。
- **不一上来建大图**：先关系表验证价值，再考虑图数据库。
- **不做打扰式提醒**：主动推送必须有每日/每周预算，可一键关闭。

## 9. 成熟度阶梯

| 层级 | 形态 | 关键新增 | 状态 |
| --- | --- | --- | --- |
| **L1** | 检索助手 | 向量检索 + 重排 + 引用 | ✅ 已有（v0.1.0） |
| **L2** | 知识管理员 | 概念/关系抽取、去重合并、孤儿/缺口分析、概念页 | 依赖图谱层 |
| **L3** | 学习教练 | 学习者模型 + 间隔重复 + 题库 + 每日队列 | **质变点** |
| **L4** | 知识伙伴 | 目标驱动、主动建议、跨笔记综述、教-回、长期演化 | 依赖 L2/L3 数据积累 |

**判断**：L2 再漂亮，如果 L3 不做，用户两周后就会回到"偶尔搜一下"。L3 才产生每天回来的理由。若只能选一个方向投入，选**学习者模型 + 间隔复习**，而不是把图画得更好看。

---

## 10. 评估也要换

现在的 `recall@k` / `faithfulness` 衡量"检索和回答对不对"。最终形态还需要衡量**学习效果**：

| 维度 | 指标 |
| --- | --- |
| 保持 | 7 天 / 30 天后同一概念的正确率 |
| 校准 | 自评把握 vs 实际正确率的偏差、过度自信率 |
| 覆盖 | 参照系覆盖率变化 |
| 依从 | 每日队列完成率（产品健康度最诚实的指标） |
| 题目质量 | 每题的区分度、被标记"题目有问题"的比例 |
| 卫生 | 孤儿率、重复率、未处理矛盾数 |

---

## 11. 什么算成功

运行 4 周后的验收标准：

- [ ] 每周至少 5 天完成每日队列
- [ ] 新增知识在 7 天后仍能答对 ≥ 85%
- [ ] 每周报告至少被打开一次，且看完
- [ ] 主人能在地图上指出 3 个"下一步要学"的概念
- [ ] 原有检索评估指标无退化
- [ ] 所有源文件未被自动修改

任何一条不达标，先修闭环，不要加功能。

## 12. 风险与开放问题

| 风险 | 说明 | 倾向的应对 |
| --- | --- | --- |
| 出题质量 | LLM 出的题可能无意义或可猜 | 出处校验 + 人工抽检 + 题目统计 + 淘汰机制 |
| 维护成本 | 图谱与题库更新需要持续投入 | 全派生、可重建、幂等、增量 |
| 知识粒度 | 概念太细变噪音，太粗不可用 | "可出题的最小单元"作为判据 |
| 依从性 | 主人不愿每天复习 | 10 分钟上限、零手工、周报正反馈 |
| 隐私 | 笔记内容发给外部 LLM | 本地模型选项、按目录排除、明确提示 |
| 平台 | 是否需要手机端 | 先本地 Web 响应式，不做原生 App |

开放问题（需要本人决策）：

1. 每天愿意投入多少分钟？（决定队列容量）
2. 主要知识领域有几个？（决定本体与参照系数量）
3. 是否接受把笔记内容发给云端 LLM 做抽取与判分？
4. 是否愿意每周花 2 分钟确认概念合并？
5. 测试题偏好：选择题为主，还是简答/自述为主？
