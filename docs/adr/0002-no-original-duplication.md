# ADR 0002：原件不双写

- **状态**：Accepted（2026-11-03 决策；2026-11-04 代码已落地）
- **日期**：2026-11-03
- **决策**：绑定 Vault / 文件夹的原件只留在文件系统。应用库不保存整篇正文。
- **不取代**：[ADR 0001](./0001-storage.md) 的 Chroma + SQLite 选型。取代的是 v0.1.0 起「父文档全文写入 `documents.sqlite3`」的做法。
- **相关**：[PLAN v4 §0.1](../../PLAN.md)

---

## 1. 背景

v0.1.0 把父文档全文放进 SQLite，检索时用这份副本做父文档扩写。产品要求 Vault / 文件夹是原件真相源，应用库只放派生数据。两套全文会分叉，也和「点原文用外部应用打开」冲突。

## 2. 决策

1. **有外部原件的文档**（绑定的 Vault 或文件夹）：SQLite 保存源路径、内容哈希、元数据、摘要、切块在源文件中的定位。向量库保存切块文本与嵌入。切块是检索用的派生副本，不是整篇原件。
2. **父文档扩写**按路径回读源文件，再按定位截取。不从 SQLite 读取整篇正文。
3. **打开原文**由本机服务用已绑定路径调用 Obsidian 或系统默认应用。对外 REST / MCP 响应不附带绝对路径。
4. **没有外部原件的正文**（仅经 API 提交的文本）：应用库保存该正文，来源标记为 `inline`。
5. **已入库的父全文**：迁移时核对源文件仍在，写入路径与哈希后删除库内全文。源文件已经不在的记录保留全文，并标为 `orphaned_copy`，直到用户处理。

## 3. 同步里不复制第二份原件

设备间同步传索引与档案：元数据、摘要、切块、嵌入、学习进度、时间线记录，以及用户许可范围内的其他隐私数据。Vault 原件要出现在另一台设备上时，以文件夹 / Vault 自身的同步为单位。应用库不因为同步再存一遍全文。

记录使用稳定 id。本机路径是该设备上的映射，不把某一台电脑的绝对路径写成跨设备主键。MVP 不做移动端，通道按多设备预留。

## 4. 后果

- 更换 embedding 时重读源文件。源文件被移走后，对应索引失效，这是不双写的代价。
- `KB_MAX_PARENT_CHARS` 改为限制从源文件读入的窗口，不再限制 SQLite 里的父全文。
- 检索质量护栏（Recall / Accuracy / Faithfulness）继续有效。父全文改回读是有意变更，不把它当成 L1 回归失败。

## 5. 落地

- 新写入遵守本决策：绑定源文件不把整篇正文写入 SQLite；无外部原件的提交标为 `inline` 并保留正文。
- 父文档扩写回读源文件，按切块定位截取。`KB_MAX_PARENT_CHARS` 限制这次从源文件读入的窗口。
- 已入库父全文用 `kb governance migrate-parents`（REST：`POST /v1/governance/migrate-parents`，admin Key）。源文件哈希与已入库哈希一致才删除库内全文并标为 `bound`；不一致则保留正文并标为 `diverged`（文件还在，需要重新入库）。源文件不在则标为 `orphaned_copy`。切块定位对齐已有向量，不重新切块。
- 父文档扩写回读前核对 `content_hash`。不一致或无法核对时退回切块文本，不把漂移后的文件送进提示词。
- 检索质量护栏（Recall / Accuracy / Faithfulness）继续有效。父全文改回读是有意变更，不把它当成 L1 回归失败。
- 用外部应用打开原文、以及对外响应去掉绝对路径，仍留在后续的本机打开原文能力，不在这次迁移里。
